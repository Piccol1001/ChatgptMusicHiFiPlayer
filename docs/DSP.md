# Equalizer and ReplayGain architecture

There is still one ExoPlayer, one MediaSession and one service. `PlaybackService` supplies a `DefaultAudioSink` with `EqualizerProcessor` in its supported AudioProcessor chain. `PcmOnlyAudioSink` rejects compressed passthrough, audio offload is disabled and floating-point sink bypass is disabled. Media3 converts other supported decoded PCM encodings to **16-bit PCM** before this processor. This is intentionally not a high-resolution hardware output or bit-perfect mode. Original files are never modified.

`AudioDspEngine` processes all 1–8 input channels independently. The 10-band and 31-band modes use RBJ peaking sections (Q 1.4 and 4.318 respectively); parametric mode has ten editable sections and supports bell, low/high shelf and low/high pass. Imported custom configurations can hold up to 32 filters. Filters at or above the actual Nyquist frequency become identity sections, and format changes rebuild/reset filter state. The response graph uses the same coefficient design and current processing sample rate; before playback it previews 48 kHz.

Settings and metadata are compiled into immutable coefficient plans on a background dispatcher. Two preallocated transposed-direct-form-II filter banks crossfade outputs over 20 ms. New changes coalesce while a transition is active. This avoids interpolating arbitrary IIR denominators or resetting audible filter state abruptly. Steady-state audio processing uses no per-sample objects, locks, file/database operations or FFT work. Media3's reusable output buffer grows only as needed. Fully bypassed audio without a visualization subscriber takes a byte-copy path, preserving 16-bit PCM exactly.

Automatic headroom samples the combined response on a logarithmic grid and at filter centers, including frequencies outside the displayed 20 Hz–20 kHz graph, and adds 0.5 dB margin. It may attenuate beyond the manual preamp slider range. This is an estimate, not an intersample/true-peak limiter or a guarantee against all transient overshoot. A counter records DSP samples exceeding full scale before PCM quantization; conversion to the sink's signed PCM range necessarily clamps overflow. Disable automatic headroom only with care.

ReplayGain reads supported ID3 TXXX and FLAC/Vorbis comment metadata through Media3. Track mode uses track gain/peak; album mode uses album gain/peak and falls back to the matching track pair when album gain is missing. No gain is invented for untagged tracks, and a preamp is applied only with an applicable tag. Peak protection caps requested gain using the corresponding file peak. Opus decoder-header gain is detected; additional ReplayGain is suppressed when that gain is active. R128 and other unrelated normalization tags are not reapplied as ReplayGain. This is static gain adjustment, not dynamic compression. MP4 free-form ReplayGain tags and other metadata conventions are not claimed supported.

The post-DSP, quantized PCM tap is bounded, single-writer/single-reader, and never waits for analysis. A consumer can drop stale snapshots or seek generations. Multichannel playback is processed on every channel; visualization monitoring uses the first two channels (mono duplicates its one channel). The tap is internal to the app, not a microphone or hardware loopback.

## Presets and persistence

The 58 built-in presets are original, deterministic voicing recipes. `BuiltInPresets.kt` documents five ten-band anchor shapes (sub, bass, body, presence and air), and explicit dB weights for every name. Genre/listening labels are suggestions, not universal mastering corrections or measured headphone calibration. Flat and Reference have zero gains. Parametric presets use the ten original centers; the 31-band mapping interpolates control gains in log frequency. Different filter bandwidths mean this is not an exact acoustic-response fit, and the UI states that limitation and previews the calculated response.

A separate `audio_dsp` DataStore preserves the mode, enabled state, all band/filter values, preamp/headroom, ReplayGain, preset favorites/recent IDs and up to 200 custom presets. The Phase 1 `player` DataStore and Room v1 database remain unchanged. Presets can be previewed, applied, saved, duplicated, renamed, deleted and imported/exported locally as versioned JSON. Imports validate names, array lengths, enum values, finite frequencies/gains/Q and practical limits before a transactional write. A failed import does not replace existing presets. No third-party headphone dataset is bundled.

## Verification boundaries

Signal tests measure actual processed sine power, channel isolation, bypass, stable coefficient conditions, headroom, ReplayGain and sample-rate changes. Processor tests check exact signed-PCM bypass and shared empty-buffer handling. Native instrumentation measures actual samples tapped from the production player in all three modes and reads/apply ReplayGain from a generated tagged MP3. Consult TESTING.md and phase reports for the final executed results; subjective clicking, battery load, Bluetooth/DAC routing and touch performance still need real-device validation.
